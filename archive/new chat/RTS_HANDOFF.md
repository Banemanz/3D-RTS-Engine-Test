## Goal

An entirely independent, from-scratch RTS engine and unrestricted **creator
suite** with a feature scope reminiscent of the SC2 Galaxy Editor / WC3 World
Editor. A creator should be able to compose games of other genres, not merely
tweak the present skirmish. The SC2 module/category matrix in
`docs/SC2_FEATURE_MATRIX.md` should guide scope; it does *not* imply SC2
compatibility or that all module functionality has already been implemented.

## Implemented in this PR

- Existing game: fixed 60Hz offline sim, A* navigation and combat chase,
  selection/commands, workers, gathering, production, buildings, enemy waves,
  win/loss, OpenGL procedural meshes, HUD, basic control groups.
- Creator backend: versioned `.rtsproject.json` map files; `DataCatalog`
  generic arbitrary typed property objects, prototype inheritance/validation,
  distinct Unit/Actor/Model catalogs; linked visuals, some runtime-backed stats;
  project placements including Unit/Mineral/Doodad/Point/Region. Per-instance
  override sections for gameplay/actor/model fields have runtime effects and
  are validated; unknown extension sections still round-trip.
- Terrain: heightfield mesh; sculpt/flatten/smooth and materials; blocked
  pathing masks; terrain-aware picking; basic undo/redo.
- Editor: F5 terrain, F7 data inspector, F9 test/play; save/load; unit/doodad/
  mineral placement; data inheritance/JSON field editing.
- CLI: `RTSProjectTool` to create/validate/edit fields and instances from scripts.
- Map logic: `TriggerEngine` with simple bounded JSON ECA, including map
  start, delayed/repeated, death and region events; spawn/grant/win/message.
- Tests: headless CTest suites, full Linux & Windows GUI builds, software OpenGL
  gameplay/editor screenshot artifacts. Validate checks before claiming green.
- Sample: `projects/terrain_showcase.rtsproject.json` generated by
  `tools/generate_terrain_showcase.py`.

## Next fundamental stages (priority)

1. **Real asset importer**: glTF/GLB/PNG/audio, materials, animations, actor
   attachment points, animation state machine, event-message actor system.
2. **Robust editor workspace**: dockable property inspector, asset browser,
   true hierarchy, selection/transform gizmos, multi-placement and per-instance
   overrides that actually take effect, full transaction-based undo/redo.
3. **Modular data-driven gameplay**: ability/effect/behavior/weapon/mover/
   validator catalogs with executable semantics, not just preserved JSON;
   units, tech trees, building production, AI configured entirely by data.
4. **Visual triggers + script**: typed event graph editor, script VM/DSL, tool
   debugger and profiler, safe script capabilities and project API, no arbitrary
   untrusted OS code.
5. **SC2 terrain layers**: cliffs, ramps, water, roads, decals, region/point/
   camera editing, multi-layer painting, collision/pathing categories.
6. **Scaling & compatibility**: spatial index, LOD/instanced render, navigation
   performance, deterministic combat, content packages and schema migrations.

Important: no one should merge the draft PR before a native Windows interactive
playtest. Do not claim real model/sound/particle runtime support merely because
catalogs accept named fields. Unknown fields currently round-trip but do not
confer engine behavior.

## How to resume

Read all Markdown documentation, current PR diff, CI runs and source in
`3D RTS (v0.3.10)/`. Build with
`cmake -S "3D RTS (v0.3.10)" -B build && cmake --build build && ctest --test-dir build --output-on-failure`
on a machine with GL+GLFW or use `-DRTS_BUILD_DEMO=OFF` for headless logic.
Continue with separate reviewable commits on the same PR branch, audit tests
after every major pass, preserve main and report exact outstanding gaps.

Additional tool: F6 is a JSON trigger inspector (create/clone/delete/inline edit);
`--trigger-editor` starts it directly. This is **not yet a visual graph or full script VM**.

## Build delivery workflow

`.github/workflows/build.yml` builds optimized Windows x64 and Linux x86_64
binaries, runs assertions-enabled CTest suites, stages a portable project layout
with CMake install rules, verifies maps and bundled files, smokes the packaged
Linux editor, and uploads platform archives as build artifacts.
Artifacts are not published as GitHub Releases or merged into main; see
`docs/BUILD_ARTIFACTS.md`. Existing Debug CI still runs and captures
OpenGL screenshots for gameplay, terrain editor and trigger editor.

## Undo/redo history update

`EditorSession` now saves bounded (32) full-project snapshots for terrain
strokes, placements, data property edits and trigger CRUD/JSON. TerrainMap can
still manage its independent history when used directly, but editor terrain
strokes disable its nested history so snapshots don't multiply recursively.
Ctrl+Z/Y work throughout the edit panels. Current limitations: undo memory
is proportional to full project size; no persistent disk recovery or coalescing
beyond each terrain brush stroke.

## Scene workspace (new)

`SceneEditor.cpp` implements the first F8 scene-object authoring tools:
viewport selection of placed objects, Shift+click/G move, J/K rotation,
comma/period scaling, ownership, Point/Region placement, region radius,
per-instance JSON override editing, stable-ID duplication and deletion.
Referenced Regions cannot be removed from the GUI. Added CTest scene editor
coverage and OpenGL screenshot smoke for the scene panel. These are keyboard-
driven controls; **not** a full transform gizmo, entity hierarchy, or
WC3/SC2-caliber actor/scene editor yet. Work remains on property widgets,
transactional editing, selection precision and real visual assets.

## Terrain navigation update

`NavigationGrid` now accepts positive per-cell traversal cost and uses a
symmetric weighted A* edge cost with an admissible octile heuristic.
`RTSSkirmish::rebuildNavigation()` derives each cell's maximum neighbor
rise/run, blocks cells above `metadata.max_walkable_slope` (default 1.25)
and applies `metadata.slope_cost_multiplier` (default 2.0) to route weights.
This is a 2.5D terrain authoring foundation, **not** yet slope physics or
per-unit movement class navigation. New tests verify detour selection,
cliff blocking and terrain-edited pathing restoration.

Pathing overlay parity: `TerrainMap::steepestSlope` is now the shared
heightfield gradient calculation used by weighted pathfinding and GPU mesh
blocked-path masks. Editor display and gameplay use the same global
`max_walkable_slope` metadata value. Mesh slope masks are precomputed once
per dirty terrain rebuild and support the default and custom thresholds.

## Build artifact UX correction

Use the **Download Windows EXE and Linux RTS Builds** workflow for actual
runnable binaries; **Tests + screenshots (NOT executables)** is not the
user download location. The Windows build now uploads the installed folder
directly through actions/upload-artifact, so its single downloadable ZIP
contains `RTSCameraTerrain.exe`, `RTSProjectTool.exe`, projects, launchers,
`START_HERE.txt`, docs and manifest without nested ZIPs. The Linux build
still wraps a tar.gz inside the Actions artifact ZIP to preserve execute
permissions. Windows Release uses MSVC static CRT. See
`docs/BUILD_ARTIFACTS.md`.

## Gameplay UI, input hardening and RTS fundamentals

The new `RTSHUDLayout.hpp` is pure headless command layout and hit testing;
`RTSHUD.hpp` renders a dark RTS-style resource bar, minimap, selected-unit
dossier and clickable command grid. `AppState` shares it for mouse hit tests
and keyboard actions, with F2 army selection, H base focus and minimap pan.
`RTSSkirmish::orderPatrol` implements back-and-forth patrol routing using
the existing waypoint planner and attack-move behavior. Stop and replacement
commands clear patrol. ESC cancels targeting before quitting.

Relevant research: SpringRTS / Recoil architecture (game-specific Lua/UI
widgets separate from core simulation), Beyond All Reason command panel
and minimap conventions. This code is newly authored, **no GPL engine
sources or widget code were copied**. Work pending: portrait/icon art,
multi-selection tiles, queue indicators, declarative command schemas, actual
production rally points, fog/LOS, zoomable minimap, user HUD layout editing.

GLFW callbacks for mouse, cursor, scroll, char and editor key now catch all
exceptions at the C entry boundary, display a notice and log errors to
`rts-editor-error.log`. `AppState::reloadFromProject` caches doodad actor
appearance to avoid validating/copying a catalog on every draw call.
Autosave every 25 seconds produces `.autosave` sibling files and newer
valid autosaves are recovered on launch. Still needs native Windows playtest;
uncaught native DLL/OpenGL crashes require callstacks/dumps.

Production rally foundation: `RTSSkirmish::setRallyPoint` accepts RMB
terrain clicks only when production buildings are selected with no mobile
units. `rallyPoints_` keyed by building ID; produced units receive their
first waypoint route automatically. Selected structures draw a gold world
marker; selected-unit panel displays pending queue count. Rally is match-
local state, not yet persisted or authored as a placement property.

Windows native fault diagnostics: `CrashReporter.hpp` registers a best-
effort `SetUnhandledExceptionFilter` with a timestamped local minidump
using DbgHelp (linked into RTSCameraTerrain only on Windows). GLFW callback
C++ exceptions already surface via the editor message and
`rts-editor-error.log`. Do not publicly upload minidumps without checking
privacy; dumps may contain process memory.

Production queue HUD: `pendingProduction(buildingId)` exposes queue size,
`productionProgress(buildingId)` exposes [0,1] for the active job or -1
when empty; `cancelSelectedProduction()` removes the latest pending job on
a selected structure and refunds its minerals and reserved supply. The
contextual rightmost command button switches from Patrol to CANCEL Q with
hotkey V. See skirmish and HUD CTests for reservation/progress/refund checks.

## Simulation-driven fog of war (2026-11-13)

`RTSVision.hpp/.cpp` stores 0=unexplored, 1=explored, 2=currently visible
per terrain vertex/cell; refreshes at 5 Hz and on reset/terrain sync. Unit
`sight_range` is a bounded 0..128 catalog property, with instance override
support through existing `resolvePlacedUnit`. LOS rays sample heights at
half-cell spacing; the eye height uses unit geometry. A revision-gated R8
OpenGL texture darkens never-seen terrain, partially shades explored ground
and leaves live terrain bright. Player enemy right-click, minimap dots,
world models and health bars respect the same visibility state. Editor modes
bypass fog so map creators see all objects. `RTSVisionTests` validates
terrain occlusion, explored persistence, GPU pixel encoding, changed-only
revision updates, and data-driven sight ranges.
Limitations: no radar, cloak/detector, height-adjusted air sensors, per-team
diplomacy/alliance LOS, ghost buildings, or line-of-fire checks yet.
